# Brainstorm: multi-agent tab isolation + agent-named tab groups

## Problem (verified)
- `local/src/main.ts:23` sets agent id = `local:${clientInfo.name}`, so every Claude Code session is `local:claude-code`. The extension treats all of them as one agent: shared default tab, shared group titled "claude-code", and agents take over each other's tabs.
- Live evidence: 8 helmsman-mcp processes running at once, each with the cwd of its own project or worktree. Two pairs share a cwd (`sbb-dev`, `dev-local-command`).
- The extension already isolates agents correctly when the ids differ (`tests/multi-agent.e2e.ts` with `agent-a`/`agent-b`).
- Secondary ways one agent can take another's tab, even with distinct ids:
  - `browser_tabs select` calls `adopt()` and overwrites another agent's ownership (`extension/src/background/tools/tabs.ts:30`).
  - An explicit `tabId` of another agent's tab is not refused (`extension/src/background/tools/tab.ts:27`), and `close` closes any tab.
  - Stop is global: `state.abort` and `stoppedUntil` are shared (`extension/src/background/index.ts:78`), so one Stop stops every agent.

## Contract
- **Outcome:** N agents using the same MCP config work in parallel. Each has its own hidden id, default tab and tab group. The AI agent names its own group after its task; until it does, the group shows the folder name plus a number. No agent can act on another live agent's tab.
- **Constraints:** existing MCP configs (`npx … helmsman-mcp`) keep working; the extension↔hub protocol is unchanged (the `agent` field already exists); works with the hub/peer model on 127.0.0.1.
- **Non-goals:** cloud/ChatGPT per-conversation identity (the endpoint is stateless, so this needs separate research); changing how a new agent picks its first tab (it may still adopt the user's active tab if nobody owns it).
- **Acceptance:**
  1. Two real Claude Code sessions in the same folder plus one in another folder produce 3 distinct groups.
  2. An agent's `name` is shown as its group title; a duplicate name gets a `·2` suffix.
  3. A tool call on another live agent's tab is refused with a clear message naming the owner group.
  4. An agent idle for 10 minutes loses ownership, and its tabs can then be adopted.
  5. Stop on agent A's tab does not stop agent B.
  6. The existing multi-agent e2e tests still pass.

## User decisions (2026-11-17)
- Group name: generated by the AI agent itself (task-based), not a fixed formula.
- Fallback before naming: cwd basename + number (`sbb-dev`, `sbb-dev·2`).
- Guard: block calls on another agent's tab unless that owner's lease has expired.
- Lease: 10 minutes without calls.

## Chosen design
1. **Identity:** in `local/src/main.ts`, `local:<client>:<random per process>`; send the cwd basename as the fallback label. The name is display only, never the identity, because shared names would bring back the collision.
2. **Naming:** `browser_tabs` gets a `name` arg (on `new`) and a `rename` action; the MCP instructions tell the agent to name its group on its first browser call. Labels are stored per agent in the extension store and deduplicated with a `·N` suffix.
3. **Guard:** in `resolveTab` / `select` / `close`, refuse when the tab's owner is another agent whose `lastSeen` is within 10 minutes; otherwise transfer ownership.
4. **Lease:** record `lastSeen` per agent on every call.
5. **Per-agent Stop:** Stop aborts only the agent owning the tab where it was pressed (per-agent AbortController and stoppedUntil).

## Trade-offs
- Random per-process id: an MCP reconnect gets a new id, so the old tabs stay locked until the 10-minute lease expires. Accepted; a parent-PID-based id is brittle because the `npm exec` layer sits in between.
- Agent-chosen names depend on the model following the instructions; the folder fallback covers it when it does not.

## Better approaches
None. The requested direction targets the verified root cause.

## Unresolved questions
- Per-agent Stop was not explicitly requested by the user; it is included because a global Stop breaks parallel work. Confirm during planning.
- Whether Codex and other clients also spawn one stdio process per session (expected, not verified).
